# План розвитку lineFONT

Найближчі пріоритети — режим «Напис» (п. 31) і внесок одного гліфа через SVG (пп. 21, 22, 25). Релізи створюються лише за запитом користувача.
Зміни схеми .lint потребують рішення щодо версії формату.

1. [x] **Екранний розмір зразка.** Висота великих літер 12–96 CSS px, перенос під доступну ширину.
2. [x] **Список відсутніх символів.** Оригінальні кластери та Unicode-коди з можливістю копіювання.
3. [x] **Збереження SVG зразка.** Поточна фраза, розмір і переноси відтворюються у файлі.
4. [x] **Локальний файл .lint у HTML.** Валідація ядром, оновлення метрик, фрази та карток, відновлення після помилки.
5. [x] **Пошук гліфів.** Усі сторінки, пошук за символом і Unicode-кодом без повторної генерації HTML.
6. [x] **Докладна картка гліфа.** Перемикачі траєкторій, напрямів, контрольних точок, advance та anchors.
7. [x] **Порівняння двох шрифтів.** Одна фраза, висота та параметри розкладки.
8. [ ] **Мобільна доступність — частково виконано.** Збільшені цілі дотику, видимий фокус, клавіатурне відкриття карток, локальне прокручування та повідомлення при блокуванні скриптів реалізовані. Перевірено Chromium із сенсорним введенням при ширині 320 px. Залишилися фізичні Android та iOS, системний вибір файлу, масштабування жестом, копіювання й завантаження SVG на цих пристроях.
9. [x] **Локалізації перегляду.** Узгоджені українські й англійські підписи, помилки та доступні назви.
10. [ ] **Якість мовних зразків — частково виконано.** Для 19 мов є технічна фраза та окрема перевірка абетки. Очікується перевірка носіями, статус кожного зразка зберігається в каталозі.
11. [x] **API точних меж штрихів.** Екстремуми кривих у Rust, спільні приклади для прив’язок, перегляду та експорту.
12. [x] **JSON Schema.** Структурна схема та визначена межа геометричної валідації.
13. [x] **Структуровані діагностики.** Код помилки, шлях поля, Unicode гліфа та позиція команди.
14. [x] **Звіт покриття мов.** Абетки та комбіновані знаки, прямі гліфи, композиції й відсутні символи.
15. [ ] **Корпус діакритики.** NFC/NFD, кілька знаків, великі й малі літери, ненульовий baseline.
16. [ ] **Політика Unicode.** Версія даних, порядок оновлення та поведінка непідтримуваних кластерів.
17. [ ] **Відтворювана розкладка.** Спільний корпус Rust, JS/WASM і C із допустимою числовою похибкою.
18. [ ] **Ліміти та fuzzing.** Пошкоджені файли, композиції, кількість команд, час і пам’ять.
19. [x] **Вимірювання швидкодії.** Великі тексти й колекції, реєстрація шрифтів, пошук і розкладка.
20. [ ] **Сумісність версій.** Зміни геометрії, метрик, невідомих полів і відтворення документів.
21. [ ] **Шаблон нового шрифту.** Шаблон SVG для побудови гліфа з базовою лінією та позначкою кроку, метадані, п’ять цілісних блоків, вільні символи, ліцензія та мінімальний приклад. У переглядачі автор вибирає шрифт і символ та завантажує шаблон із метриками саме цього шрифту.
22. [ ] **Імпорт SVG.** Трансформації, одиниці, перетворення у M/L/C та повідомлення про втрати. Після імпорту SVG одного гліфа показати траєкторію пера. Якщо штрих перетворено на контур із двома краями, пояснити ризик подвійного проходу й дати автору перевірити малюнок. Плаский експорт шрифту розгортає alias і composite у траєкторії зі збереженням кроку.
23. [ ] **Порівняння версій.** Зміни гліфів, advance та anchors із візуальним накладанням.
24. [ ] **CI внесків шрифтів.** Валідація, повнота блоків, ліцензія та артефакти рев’ю.
25. [ ] **Посібник автора.** Редагування окремого гліфа з перевіркою результату, каталог шрифтів із ліцензіями та покриттям. Наскрізний приклад SVG → .lint → композиція → PR. Для внеску однієї Ґ автор повертає відредагований шаблон у переглядач, перевіряє «Ґ Г ґ» і «ґвинт» та завантажує перевірений файл .lint.
26. [ ] **Інтеграція bagLING.** Закріплена версія, збереження шрифтів, спільна геометрія екрана й експорту.
27. [ ] **Прив’язки C та Python.** Приклади установки на підтримуваних платформах і узгоджені помилки.
28. [ ] **Фізичні перевірки.** Плотер і гравер, малі розміри, відкриті штрихи, піднімання інструмента й діакритика. Опублікувати напис «Ґвинт М3 · ⌀6 ±0,1 мм · 45° · αβ» заввишки 2, 3 і 4 мм, вихідний текст, використані шрифти, SVG, PDF і фото результату з указаною товщиною пера. На фото перевірити читабельність коми, крапки та діакритики.
29. [x] **Оптимізація маршруту.** Довжина холостого ходу, контроль результату й збереження канонічного порядку.
30. [ ] **MCP-адаптер.** Після стабілізації API інструментів надати валідацію, покриття, порівняння та зразки з лімітами ресурсів.
31. [ ] **Режим «Напис» в офлайн-переглядачі.** Вставлення довгого багаторядкового тексту або відкриття .txt. Полотно росте за текстом, Enter задає новий рядок, необов’язкова ширина в міліметрах вмикає автоматичний перенос. Висота літер, міжряддя, міжлітерний інтервал, товщина штриха та поля задаються у фізичних одиницях. Експортувати весь напис зі спільної розкладки в SVG або односторінковий PDF за розміром напису з полями. Перевірити останній рядок довгого тексту, переноси, висоту 4 мм після імпорту SVG та друку PDF у масштабі 100 %, а також один прохід пера вздовж відкритого штриха.
32. [ ] **DXF готового напису.** Після SVG і PDF додати експорт штрихів як звичайної CAD-геометрії. Відкрити результат у сторонній CAD-програмі й перевірити фізичні розміри та відкриті траєкторії.
33. [ ] **Імпорт цілих шрифтів.** Спочатку підтримати SVG-шрифти, сумісні з Hershey Text, потім LFF із LibreCAD. Переносити Unicode-відповідності й метрики та показувати втрати перетворення. Для неповного обов’язкового блоку перелічити відсутні знаки й запропонувати доповнити блок або пропустити його цілком. Підтримку SHP/SHX розглянути за конкретним запитом користувачів AutoCAD.
34. [ ] **Рекомендований крок рядків.** Узгодити необов’язкову метрику шрифту в його власних одиницях і правило для наявних файлів. Переглядач масштабує рекомендацію за обраною висотою літер і дозволяє змінити міжряддя вручну. Перевірити на українських виносних елементах та грецьких літерах із наголосами.
